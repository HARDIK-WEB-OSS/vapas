# Decisions log

Decisions taken during the autonomous build (from 21 Nov 2026). Each one follows CLAUDE.md and the safest option. Product policy decisions that change user-facing behaviour also belong in `docs/product_policy.md`; this log records engineering and process choices.

| Date | Decision | Options considered | Reason | Reversible |
|---|---|---|---|---|
| 2026-11-21 | Per-request user transaction commits before the response is sent (`Depends(current_user, scope="function")`) | (a) keep FastAPI default `request` scope and make the frontend poll `awaiting_upload` too; (b) function scope | With (a) every write endpoint can answer before its data is visible, a real consistency bug for any client, not only this page. Function scope fixes the cause | yes |
| 2026-11-21 | Anonymous visitors skip `/auth/refresh` using a non-secret `localStorage` hint set at login | (a) always call refresh; (b) a readable non-HttpOnly cookie; (c) localStorage hint | (a) costs a request and a console error on every public page; (b) adds a cookie to every request; (c) holds no secret and fails safe (if storage is blocked, the app still tries to refresh) | yes |
| 2026-11-21 | Lighthouse measured on public pages only, median of 3, API off | measure signed-in pages with a scripted session | Lighthouse cannot hold the in-memory access token; reporting only what was measured | yes |
| 2026-11-21 | CI e2e job reuses `docker compose up --wait api` to run roles, migrations and bucket setup, then stops the api container and runs API + worker from source | separate compose profile for e2e | Same path as the existing backend job, no new compose surface; Playwright starts API and worker with the local mail outbox | yes |
| 2026-11-21 | Backend host: Fly.io region `bom` (Mumbai), api and worker as process groups of one app; Postgres: Supabase `ap-south-1` (Mumbai); frontend: Vercel `bom1`; object storage: Cloudflare R2 | Render, Railway (no India region); Neon (no Mumbai region found on its regions page); AWS RDS ap-south-1 (more setup, cost after free tier) | India region where available, as CLAUDE.md asks; one image for api, worker and migrations. R2 has no India location; accepted because raw statements live under 1 hour and are deleted. Sources: fly.io/docs/reference/regions, supabase.com/docs/guides/platform/regions, neon.com/docs/introduction/regions | yes |
| 2026-11-21 | Client IP comes from a configured trusted header (`CLIENT_IP_HEADER`, production `Fly-Client-IP`), else the socket peer | Trust `X-Forwarded-For` with `FORWARDED_ALLOW_IPS="*"` | With all proxies trusted, uvicorn takes the left-most `X-Forwarded-For` entry, which the client controls, so per-IP limits could be bypassed. | 2026-11-21 | General API limits built as middleware: 120 burst / 60 per min per user, 600 burst / 300 per min per IP (numbers from `system_design.md` 6.2); in-process fallback when Redis is down; auth routes still fail closed | Per-route decorators | One place, covers every route; matches the failure-modes table | yes |
| 2026-11-21 | Request bodies capped at 64 KiB (413), chunked bodies buffered up to the cap | Rely on upstream proxy limits | Statements never pass through the API (presigned upload), so 64 KiB is far above any JSON body | yes |
| 2026-11-21 | Presigned PUT signs `Content-Length` | Check size only at confirm | Without it the URL could overwrite the object with a larger file after confirm and before parsing | yes |
| 2026-11-21 | Bucket lifecycle rule: raw uploads expire after 1 day; `configure_bucket.py` replaces the local-only `create_local_bucket.py` | Keep lifecycle as design only | The design lists it as the backstop for the 1-hour deletion; lifecycle rules work in whole days | yes |
| 2026-11-21 | Email provider: Resend over HTTPS with an idempotency key; auth emails fail soft (logged as error), reminders retry hourly with an error log after 24 failed attempts | Brevo; failing signup with 503 | Failing signup would leak whether an email is registered during an outage; reminders already have the in-app banner | yes |
| 2026-11-21 | Sentry for API and worker only, behind `SENTRY_DSN`, with a scrubber (no request bodies, headers, cookies, query strings, user, local variables or breadcrumb data) | Frontend Sentry SDK | Keeps PII out of a third party; the frontend has no server-side state worth tracking for the pilot | yes |
| 2026-11-21 | API docs (`/docs`, `/redoc`, `/openapi.json`) are off outside local and test | Leave on | Smaller attack surface; CSP `default-src 'none'` on every other API response | yes |

| 2026-11-21 | Database connection failures answer 503 `temporarily_unavailable`; object store failure at confirm answers 503 | Raw 500 | Matches the failure-modes table; the client can retry | yes |
